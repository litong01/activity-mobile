# Running the app on Android (emulator and device)

This guide describes how to start the Metro server and run the app on the Android emulator (including from Android Studio).

---

## Prerequisites

- **Node.js** (v22.x recommended; see `.nvmrc` or `package.json` / Volta if used)
- **Android Studio** – [developer.android.com/studio](https://developer.android.com/studio)
- **Android SDK** – installed via Android Studio (SDK Manager)
- **Android emulator** – at least one AVD (Android Virtual Device) created in Android Studio

After installing Android Studio, ensure **ANDROID_HOME** is set (e.g. in `~/.zshrc` or `~/.bashrc`):

```bash
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/emulator:$ANDROID_HOME/platform-tools
```

On Windows, typical value is `%LOCALAPPDATA%\Android\Sdk`.

Gradle also needs the SDK path in **android/local.properties** (especially when building from Android Studio, which may not see your shell’s ANDROID_HOME). After generating the **android/** folder, run:

```bash
npm run android:local-properties
```

That creates **android/local.properties** with `sdk.dir` from ANDROID_HOME (or the default Mac path). If you see "SDK location not found", run this and try building again.

---

## Port 8082

This project runs Metro on **port 8082** (see `metro.config.js` and `package.json`). The Android app is configured to use that port. If something else is using 8081, you don’t need to change it for this project.

## First-time setup (generate Android project)

The **android/** folder is generated by Expo and is not committed. Generate it once (and again after adding native dependencies or changing app config):

```bash
npm install
npx expo prebuild --platform android
```

Then create **android/local.properties** so Gradle finds the SDK:

```bash
npm run android:local-properties
```

Or, to regenerate from scratch:

```bash
npm run prebuild:clean
```

(`prebuild:clean` regenerates both **ios/** and **android/**; for Android only, use `npx expo prebuild --platform android --clean`.) After any prebuild that (re)creates **android/**, run **`npm run android:local-properties`** again (see below).

---

## When to run `npm run android:local-properties`

**android/local.properties** is not in the repo (android/ is gitignored). The SDK path in that file is **lost** when:

| Situation | Do you need to run it? |
|-----------|------------------------|
| **First time** you generate **android/** (e.g. after `npx expo prebuild --platform android`) | **Yes** – the new folder has no local.properties. |
| **After** `npm run prebuild:clean` or `npx expo prebuild --platform android --clean` | **Yes** – prebuild deletes and recreates **android/**, so local.properties is gone. |
| **New clone** of the repo, then you run prebuild | **Yes** – android/ didn’t exist (or you just generated it). |
| **Normal development** (only running `npm run android`, building from Android Studio, no prebuild) | **No** – local.properties stays until you regenerate android/. |
| **Switching machines** (e.g. new laptop) | **Yes** – android/ is usually regenerated or copied; run it after prebuild so sdk.dir matches that machine. |

**Summary:** Run **`npm run android:local-properties`** whenever **android/** has just been (re)created (first-time setup or after any prebuild that touches Android). You don’t need to run it again until you regenerate **android/** or set up the project on another machine.

## How to run on the Android emulator

### 1. Start Metro

In a terminal, from the project root:

```bash
npm start
```

Leave this running. Wait until you see something like **“Metro waiting on…”** and the Expo menu (e.g. “Press a │ open Android”).

### 2. Run the app on the emulator

**Option A – From the same terminal (recommended)**

With Metro running, press **`a`** to open the app on the Android emulator. Expo will start an emulator if needed and install/run the app with the correct dev server URL.

**Option B – From a second terminal**

```bash
npm run android
```

This builds and runs the app on the default emulator/device. Metro must already be running in another terminal (step 1).

**Option C – From Android Studio**

1. Start Metro (step 1) in a terminal and leave it running.
2. Open the project in Android Studio (see [Open the project in Android Studio](#open-the-project-in-android-studio) below).
3. In Android Studio, choose your emulator (or device) in the device dropdown and click **Run** (▶).

The app will connect to Metro at **localhost:8082** (emulator uses 10.0.2.2:8082 to reach the host’s localhost).

---

## Open the project in Android Studio

1. Generate the Android project if you haven’t (see [First-time setup](#first-time-setup-generate-android-project)).
2. Open **Android Studio**.
3. **File → Open** (or “Open an existing project”).
4. Go to your project folder and select the **`android`** directory (the one that contains `build.gradle` and `app/`).
5. Click **Open**. Wait for Gradle sync to finish.
6. In the toolbar, open the device dropdown and select an **Android emulator** (or create one via **Device Manager**).
7. Click **Run** (▶) to build and run the app.

Make sure **Metro is already running** (`npm start` in a terminal) so the app can load the JS bundle.

## Start the Android emulator (without running the app)

If you want to start the emulator first, then run the app:

**From Android Studio**

- **Tools → Device Manager** (or the device manager icon), then click ▶ next to an AVD.

**From the command line**

```bash
$ANDROID_HOME/emulator/emulator -avd <AVD_NAME>
```

List AVDs:

```bash
$ANDROID_HOME/emulator/emulator -list-avds
```

## Physical Android device

1. Enable **Developer options** and **USB debugging** on the device.
2. Connect the device via USB (or use wireless debugging if set up).
3. Run **`npm start`** on your machine.
4. Run **`npm run android`** (or run from Android Studio with the device selected). The device must be on the same network as your machine for Metro; for USB, the app typically uses your machine’s IP and port 8082.

## Troubleshooting

### "SDK location not found" / "sdk.dir path in local.properties"

Gradle can’t find the Android SDK. Either **ANDROID_HOME** isn’t set where Gradle runs (e.g. in Android Studio), or **android/local.properties** doesn’t exist (the **android/** folder is generated by prebuild and usually gitignored, so that file isn’t in the repo).

**Fix 1 – Create local.properties (recommended)**

From the project root:

```bash
npm run android:local-properties
```

That writes **android/local.properties** with `sdk.dir` using your ANDROID_HOME (or the default Mac path `~/Library/Android/sdk`). Then sync/build again.

**Fix 2 – Set ANDROID_HOME**

In your shell config (e.g. `~/.zshrc`):

```bash
export ANDROID_HOME=$HOME/Library/Android/sdk
```

Then open Android Studio **from the terminal** so it inherits PATH: `open -a "Android Studio" android`. If Gradle still can’t find the SDK, use Fix 1 as well.

---

### "A problem occurred starting process 'command 'node''" / "Could not start 'node'" (error=2, No such file or directory)

Gradle runs `node` during the build (Expo/React Native need it), but **Android Studio doesn’t see `node`** when it’s started from the dock or Spotlight. GUI apps on macOS don’t use your terminal PATH (e.g. from nvm, Volta, or Homebrew).

**Fix 1 – Launch Android Studio from the terminal (recommended)**

From your project root (so your shell’s PATH is used):

```bash
cd /path/to/activity-mobile
open -a "Android Studio" android
```

Or start Android Studio from an existing terminal window (e.g. `open -a "Android Studio"`), then **File → Open** and choose the **android** folder. The IDE will inherit your PATH and Gradle will find `node`.

**Fix 2 – Put Node on a path that GUI apps see**

Create a symlink so `node` is in `/usr/local/bin` (often on the default PATH for GUI apps):

```bash
sudo ln -sf $(which node) /usr/local/bin/node
```

If you use **nvm**:

```bash
sudo ln -sf "$NVM_DIR/versions/node/$(nvm version)/bin/node" /usr/local/bin/node
```

Then restart Android Studio (you can open it from the dock). Gradle should now find `node`.

---

### "externalNativeBuildCleanDebug" / "add_subdirectory given source ... which is not an existing directory"

CMake is looking for codegen JNI folders (e.g. for react-native-gesture-handler, react-native-reanimated, react-native-worklets, react-native-keychain) that don’t exist yet. That often happens after a clean or when the native build runs before codegen.

**Fix – Clear native cache and do a full build (no clean)**

1. From the **project root**, remove the Android native/build caches:
   ```bash
   rm -rf android/app/.cxx android/app/build android/build
   ```
2. Run a **full build** so Gradle runs codegen first, then the native build. Do **not** run “Clean” in Android Studio first.
   - From project root: `npm run android`
   - Or from `android/`: `./gradlew assembleDebug`
3. If it still fails, regenerate the Android project and build again:
   ```bash
   npx expo prebuild --platform android --clean
   npm run android
   ```

---

### "Invalid Gradle JDK configuration found"

Android Studio is trying to use a JDK that no longer exists or is invalid (e.g. after an update or a moved JDK).

**Quick fix (in the dialog):**

- Click **"Use Embedded JDK"** so Gradle uses the JDK bundled with Android Studio (`/Applications/Android Studio.app/Contents/jbr/Contents/Home` on macOS). This is the simplest and recommended option.

**If you don’t see the dialog or want to change it later:**

1. **Android Studio → Settings** (macOS: **Preferences**).
2. Go to **Build, Execution, Deployment → Build Tools → Gradle**.
3. Under **Gradle JDK**, choose **"Embedded JDK"** (or **"jbr-17"** / **"17"** if listed).
4. Click **Apply** then **OK**.

After that, sync the project (e.g. **File → Sync Project with Gradle Files**) and try building again.
